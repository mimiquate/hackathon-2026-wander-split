# Tailwind with a token-mapped theme, not inline-style components

The landing page's design handoff (Ruta Terracota design system) ships its React components as pure inline `style={{...}}` objects referencing `var(--token)`, with hover/press state faked via `useState` and mouse handlers since inline styles can't express CSS pseudo-classes. We instead style ported components with Tailwind utilities, extending `tailwind.config`'s colors/spacing/radius/fonts to point at the same `var(--token)` custom properties, so `:hover`/`:active`/`:focus-visible` are real CSS. This costs upfront config work (the design system's spacing scale is irregular, not a 4px grid) but avoids re-deriving pseudo-class behavior in JS for every component, and is the more idiomatic pattern for the Next.js app this page is the first slice of.
