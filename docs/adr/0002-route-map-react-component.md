# Route map as a React component, not a ported custom element

The design handoff's `route-map.js` is a vanilla Web Component (`customElements.define('route-map', ...)`) that reads `window.d3`/`window.topojson` loaded via global CDN `<script>` tags, and polls until they're defined. We reimplement it as a native React component (client-rendered, `useRef` + `useEffect` + `ResizeObserver`) with `d3-geo`, `d3-selection`, and `topojson-client` as regular npm dependencies, keeping the same projection/layer-order/coordinate logic. The custom-element wrapper and global-script loading only made sense for the prototype's own runtime; a real npm dependency avoids the "poll until globals exist" hack and fits Vitest/Playwright/React conventions better than a hand-registered custom element would.
